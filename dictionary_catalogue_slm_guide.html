Building a Small Language Model from Rules for a Dictionary Catalogue

A single-page Python-oriented design for corpus extraction, catalogue-aware parsing, tokenization, training examples, a small causal Transformer, evaluation, and generation.

Source basis. The attached EPUB is Charles A. Cutter's Rules for a Dictionary Catalogue, third edition (1891), U.S. Bureau of Education Special Report on Public Libraries—Part II. The Project Gutenberg edition is eBook No. 59215 and is identified by Gutenberg as public domain in the United States (Project Gutenberg, 2019/2020). This page uses the attached book as the domain corpus and modern Python/PyTorch sources for the machine-learning implementation.

1. Goal: a small domain language model

The project is not intended to reproduce a general-purpose chatbot. It is a compact autoregressive language model trained to learn the vocabulary, phrasing, definitions, entry rules, and relationships present in Cutter's catalogue text. Given preceding tokens, it learns to assign scores to possible next tokens.

context tokens
      |
      v
 P(next token | preceding tokens)
      |
      v
next-token prediction
      |
      +---- appended to context ----+
                                    |
                                    +----> model again

The corpus is especially useful pedagogically because Cutter explicitly organizes knowledge around objects, means, definitions, author-entry, title-entry, subject-entry, form-entry, references, headings, titles, editions, imprints, notes, language, punctuation, arrangement, appendices, and an index. Those divisions can be retained as metadata instead of flattening the entire book immediately.

2. What the attached catalogue contributes

Cutter states three broad catalogue objectives: enable a person to find a book when author, title, or subject is known; show what the library has by an author, on a subject, or in a kind of literature; and assist in choosing a book by edition or character. He associates those objectives with author, title, subject, form, edition/imprint, reference, and note mechanisms (Cutter, 1891).

4. Corpus and training schema

A useful intermediate record separates source structure from model tokens:

{
  "document": "Rules for a Dictionary Catalogue",
  "author": "Charles A. Cutter",
  "edition": "Third edition",
  "year": 1891,
  "section": "III. Subject-Entry",
  "record_type": "rule",
  "text": "...source text...",
  "source_file": "...xhtml",
  "sequence": 123
}

Then serialize selected records into a training stream:

<BOS>
<SECTION_SUBJECT_ENTRY>
<RULE> ... text from the source ...
<RULE> ... next rule ...
<EOS>

For a token sequence [t0,t1,t2,t3,t4], next-token training is shifted by one position:

INPUT X:   t0  t1  t2  t3
TARGET Y:  t1  t2  t3  t4

At each position:
t0          -> predict t1
t0 t1       -> predict t2
t0 t1 t2    -> predict t3
t0 t1 t2 t3 -> predict t4

5. Extract the attached EPUB with Python

An EPUB is a ZIP-based container. For a dependency-light teaching version, Python's zipfile can enumerate its XHTML members. The example below deliberately uses a small standard-library HTML parser rather than treating markup tags as training prose.

from pathlib import Path
from zipfile import ZipFile
from html.parser import HTMLParser
import re

EPUB = Path("Creating_Dictionary_Catalouge_Librarians_pg59215-images-3.epub")


class TextExtractor(HTMLParser):
    def __init__(self):
        super().__init__()
        self.parts = []

    def handle_data(self, data):
        if data.strip():
            self.parts.append(data.strip())

    def text(self):
        return "\n".join(self.parts)


def extract_epub(epub_path):
    documents = []

    with ZipFile(epub_path) as book:
        members = sorted(
            name for name in book.namelist()
            if name.lower().endswith((".xhtml", ".html", ".htm"))
        )

        for name in members:
            raw = book.read(name).decode("utf-8", errors="replace")

            parser = TextExtractor()
            parser.feed(raw)

            text = parser.text()
            text = re.sub(r"[ \t]+", " ", text)
            text = re.sub(r"\n{3,}", "\n\n", text)

            documents.append({
                "source_file": name,
                "text": text.strip()
            })

    return documents


docs = extract_epub(EPUB)

print("XHTML documents:", len(docs))
print(docs[0]["text"][:1000])

Do not remove punctuation blindly. In this corpus, punctuation, capitalization, abbreviations, headings, and alphabetical conventions can themselves carry cataloguing information.

6. Catalogue-aware parsing

Parsing here means recognizing document structure; it is distinct from neural tokenization. A first pass can classify headings and common record forms with regular expressions. Python's re module supplies compiled regular-expression matching operations (Python Software Foundation, 2026).

import re

SECTION_PATTERNS = [
    (r"^I\.\s+Author-Entry", "SECTION_AUTHOR_ENTRY"),
    (r"^II\.\s+Title-Entry", "SECTION_TITLE_ENTRY"),
    (r"^III\.\s+Subject-Entry", "SECTION_SUBJECT_ENTRY"),
    (r"^IV\.\s+Form-Entry", "SECTION_FORM_ENTRY"),
    (r"^DEFINITIONS\.?$", "SECTION_DEFINITIONS"),
    (r"^OBJECTS\.?$", "SECTION_OBJECTS"),
    (r"^MEANS\.?$", "SECTION_MEANS"),
]

def classify_line(line):
    clean = line.strip()

    for pattern, label in SECTION_PATTERNS:
        if re.match(pattern, clean, flags=re.IGNORECASE):
            return label

    if re.match(r"^\d+\.", clean):
        return "NUMBERED_ITEM"

    if clean.lower().startswith(("see ", "see also ")):
        return "REFERENCE"

    return "TEXT"

For this historical document, parsing should be conservative: preserve the source text first, then add labels. A parser that guesses too aggressively can inject incorrect structure into the training data.

7. Tokenization

7.1 Educational tokenizer

Start with a transparent tokenizer so every transformation can be inspected.

import re

TOKEN_RE = re.compile(
    r"""<[A-Z_]+>        # structural tokens
      | [A-Za-zÀ-ÖØ-öø-ÿ]+(?:['’-][A-Za-zÀ-ÖØ-öø-ÿ]+)*
      | \d+(?:\.\d+)?
      | [^\s]
    """,
    re.VERBOSE
)

def tokenize(text):
    return TOKEN_RE.findall(text)

sample = "<DEFINITION> Author, in the narrower sense, is the person..."
print(tokenize(sample))

7.2 Vocabulary and integer IDs

SPECIAL = ["<PAD>", "<UNK>", "<BOS>", "<EOS>"]

def make_vocab(tokens):
    vocab = SPECIAL + sorted(set(tokens))
    stoi = {token: i for i, token in enumerate(vocab)}
    itos = {i: token for token, i in stoi.items()}
    return vocab, stoi, itos

def encode(tokens, stoi):
    unk = stoi["<UNK>"]
    return [stoi.get(token, unk) for token in tokens]

def decode(ids, itos):
    return [itos[i] for i in ids]

7.3 Why move to subwords later?

A word-level vocabulary is easy to understand but handles rare spellings and morphological variants inefficiently. A later version can use a subword model. SentencePiece, for example, can train subword units directly from raw sentences rather than requiring pre-tokenized word input (Kudo & Richardson, 2018). For the first experiment, however, the regex tokenizer makes the complete pipeline visible.

8. Build fixed-length training examples

import torch
from torch.utils.data import Dataset

class CatalogueDataset(Dataset):
    def __init__(self, token_ids, context=128):
        self.ids = token_ids
        self.context = context

    def __len__(self):
        return max(0, len(self.ids) - self.context)

    def __getitem__(self, index):
        chunk = self.ids[index:index + self.context + 1]

        x = torch.tensor(chunk[:-1], dtype=torch.long)
        y = torch.tensor(chunk[1:], dtype=torch.long)

        return x, y

Split the corpus before training. For a single book, a simple chronological split is useful for a first experiment—for example, approximately 90% training and 10% validation—while recognizing that sections differ in content and length.

9. A small causal Transformer in PyTorch

PyTorch describes an embedding as a lookup from integer indices to vectors, while its Transformer encoder layer contains self-attention and a feed-forward network (PyTorch Contributors, 2026a, 2026b). We can use those components with a causal mask so a token cannot look ahead at the answer it is supposed to predict.

import torch
import torch.nn as nn

class SmallCatalogueLM(nn.Module):
    def __init__(
        self,
        vocab_size,
        context=128,
        d_model=128,
        heads=4,
        layers=4,
        ff=512,
        dropout=0.1
    ):
        super().__init__()

        self.context = context

        self.token_embedding = nn.Embedding(vocab_size, d_model)
        self.position_embedding = nn.Embedding(context, d_model)

        block = nn.TransformerEncoderLayer(
            d_model=d_model,
            nhead=heads,
            dim_feedforward=ff,
            dropout=dropout,
            activation="gelu",
            batch_first=True,
            norm_first=True
        )

        self.transformer = nn.TransformerEncoder(
            block,
            num_layers=layers
        )

        self.norm = nn.LayerNorm(d_model)
        self.output = nn.Linear(d_model, vocab_size)

    def forward(self, token_ids):
        batch, length = token_ids.shape

        positions = torch.arange(
            length,
            device=token_ids.device
        ).unsqueeze(0)

        x = (
            self.token_embedding(token_ids)
            + self.position_embedding(positions)
        )

        # True above the diagonal prevents access to future tokens.
        causal_mask = torch.triu(
            torch.ones(length, length, device=token_ids.device),
            diagonal=1
        ).bool()

        x = self.transformer(
            x,
            mask=causal_mask
        )

        x = self.norm(x)

        return self.output(x)

B = batch size, T = context length, D = embedding/model dimension, and V = vocabulary size.

10. Training loop

For next-token prediction, each vocabulary item acts as a possible target class. PyTorch's CrossEntropyLoss accepts unnormalized logits and target class indices. AdamW supplies the parameter-update step (PyTorch Contributors, 2026c, 2026d).

import torch
import torch.nn as nn

device = (
    "cuda" if torch.cuda.is_available()
    else "mps" if torch.backends.mps.is_available()
    else "cpu"
)

model = SmallCatalogueLM(
    vocab_size=len(vocab),
    context=128
).to(device)

optimizer = torch.optim.AdamW(
    model.parameters(),
    lr=3e-4,
    weight_decay=0.01
)

criterion = nn.CrossEntropyLoss()

for epoch in range(10):

    model.train()
    total_loss = 0.0

    for x, y in train_loader:
        x = x.to(device)
        y = y.to(device)

        optimizer.zero_grad()

        logits = model(x)

        loss = criterion(
            logits.reshape(-1, logits.size(-1)),
            y.reshape(-1)
        )

        loss.backward()

        torch.nn.utils.clip_grad_norm_(
            model.parameters(),
            max_norm=1.0
        )

        optimizer.step()

        total_loss += loss.item()

    average = total_loss / len(train_loader)
    print(f"epoch={epoch + 1} train_loss={average:.4f}")

11. Generation

At inference time, feed a prompt, take the logits at the final position, convert them to a probability distribution, sample a token, append it, and repeat.

@torch.no_grad()
def generate(model, ids, max_new_tokens=80, temperature=0.8):
    model.eval()

    for _ in range(max_new_tokens):

        x = torch.tensor(
            [ids[-model.context:]],
            dtype=torch.long,
            device=next(model.parameters()).device
        )

        logits = model(x)
        next_logits = logits[:, -1, :] / temperature

        probabilities = torch.softmax(next_logits, dim=-1)

        next_id = torch.multinomial(
            probabilities,
            num_samples=1
        ).item()

        ids.append(next_id)

    return ids

A lower temperature makes the distribution sharper; a higher temperature increases randomness. For a small single-book model, generated prose may imitate local language without reliably reproducing correct cataloguing rules. Treat it as a learning model, not an authoritative cataloguing system.

12. Evaluation

Keep validation examples out of parameter updates. Track validation cross-entropy and optionally perplexity:

perplexity = exp(validation_loss)

Also perform domain-specific checks:

CheckQuestion
Held-out lossDoes performance improve on text not used for gradient updates?
MemorizationIs the model simply reproducing long passages from this small corpus?
StructureDoes it learn that author-, title-, and subject-entry are different catalogue concepts?
TerminologyDoes it use terms such as entry, reference, heading, subject, imprint, and edition in plausible contexts?
Ground-truth comparisonWhen asked about a rule, does generated language agree with the source passage?
